# SECURITY.md — セキュリティ方針

> ランキング・公開作業のときに必ず読む。脅威と対策の一覧。

## 前提(正直な期待値)

クライアント側だけで動くゲームの**チート完全防止は不可能**(コードは全部ユーザーの手元にある)。
このプロジェクトの目的は「**カジュアルな不正の抑止**」。過剰な実装はしない。
個人情報は扱わない(ニックネーム+スコア+日時のみ)。

## 脅威と対策

| # | 脅威 | 対策 |
|---|---|---|
| 1 | XSS:悪意あるニックネーム(`<script>`等)がランキング表示で実行される | 表示は必ず `textContent`(`innerHTML` 禁止)。入力はクライアント/サーバー両方で長さ(1〜12文字)・制御文字除去を検証 |
| 2 | スコア改ざん:APIに直接デタラメなスコアをPOST | クライアントから直接INSERTさせない。Edge Function経由のみで検証(下記) |
| 3 | DBへの直接書き込み・削除 | RLS:scoresテーブルは匿名ロールに SELECT のみ許可。INSERT/UPDATE/DELETE は service role(Edge Function内)のみ |
| 4 | スパム連投 | Edge Function で同一IPのレート制限(例:1分に3回まで) |
| 5 | service role キーの漏洩 | クライアントコード・公開リポジトリに置かない。Supabaseの環境変数(Secrets)のみ。anonキーは公開前提の設計なのでOK |
| 6 | 依存ライブラリの改ざん(CDN汚染) | Matter.js はファイル同梱(CDN非依存) |

## Edge Function でのスコア検証(脅威2の詳細)

1. **型・範囲チェック**:scoreは整数、0 < score ≦ 上限値(理論上ありえる最大値、要調整)
2. **プレイ時間整合**:ゲーム開始時にEdge Functionから「プレイトークン」(署名付き・開始時刻入り)を発行。
   送信時にトークン必須とし、経過時間に対してスコアが速すぎないか(1秒あたり最大スコア)をチェック
3. **ニックネーム検証**:1〜12文字、制御文字・改行を拒否

## 公開時チェックリスト(2026-06-11 F7で実施済み)

- [x] リポジトリに service role キー・Secretsが含まれていない(履歴も含む。grepで実測)
- [x] ニックネーム表示箇所がすべて `textContent` である(`<img onerror>`注入テストで実地確認)
- [x] RLSが有効で、匿名ロールでINSERTできないことを実測確認(401が返る)
- [x] Edge Function に不正値(トークンなし・巨大スコア・長い名前・短いプレイ時間・連投)を投げて拒否されることを確認
- [x] Edge Function の許可オリジンを `https://pon10s.github.io` に限定(プリフライト応答で実測)

※許可オリジン限定の副作用:ローカル(localhost)で開いた場合、ゲームは遊べるがランキング送信・表示は通信エラーになる(仕様)。
